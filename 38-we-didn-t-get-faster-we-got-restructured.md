# We Didn't Get Faster. We Got Restructured.

When MVC arrived, it wasn't received as "the same web development, just quicker." People used to writing single-page logic top to bottom felt real friction — where does this piece go, why is this split into three files now, why can't I just write it the way I already know. The friction wasn't a sign MVC was wrong. It was a sign something structural had actually changed, not just accelerated.

I think AI in software engineering is the same shock, mostly misread.

From outside engineering, the visible number is speed. Features ship faster. A prototype that used to take a week takes an afternoon. That's real, and it's the number that gets reported upward, because it's the number that's easy to see and easy to compare quarter over quarter.

From inside engineering, something else is happening, and it doesn't show up on that chart at all. Planning changed. Review changed. The old assumption — a human wrote every line, so a baseline of judgment was already baked into the code before anyone reviewed it — no longer holds by default. That assumption used to be invisible, because it was always true. Now it isn't automatically true, and everything that assumption used to quietly support has to be rebuilt on purpose: how much gets reviewed, at what depth, by whom, before code is trusted the way it used to be trusted by default.

That's not speed. That's restructuring — the same kind MVC forced, just in a different layer of the work.

The gap between these two readings is the actual culture shock. The business watches acceleration and reasonably asks for more of it. Engineers are living through a rebuild of the practice itself, and if that rebuild goes unacknowledged — treated as "we're just going faster now" instead of "we're operating under different assumptions now" — the rebuild happens badly. Corners that used to be safe to cut because a human's judgment was already in the code are still being cut, except the judgment isn't there anymore either.

> Every real structural shift looks like a speed boost from far enough away, and feels like a rebuild from inside it. Both readings are true. Only one of them tells you what to actually plan for.

Good planning with AI isn't optional groundwork before the "real" gains start. It's what decides whether the rebuild lands somewhere solid, the way MVC eventually did once the friction settled — or somewhere that just looks fast until the missing structure catches up with it.

Nothing here is really about AI being new. It's about recognizing which kind of change you're actually living through, so you plan for the right one instead of celebrating the wrong number.
